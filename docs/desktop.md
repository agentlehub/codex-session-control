# Desktop support

Desktop integration is optional. CLI and MCP work without it. Codex Session Control supports Desktop integration only with builds from the [`agentlehub/codex-desktop-linux` fork](https://github.com/agentlehub/codex-desktop-linux). The fork's `main` branch contains the latest upstream Desktop code plus the changes required for Codex Session Control. Builds from the original repository are not supported. Follow [Build and install the supported Desktop](#build-and-install-the-supported-desktop) to create a compatible build.

## Build and install the supported Desktop

Clone the supported fork and enter its directory:

```bash
git clone https://github.com/agentlehub/codex-desktop-linux.git
cd codex-desktop-linux
```

Enable Codex Session Control support in the local build configuration:

```bash
CODEX_BOOTSTRAP_NONINTERACTIVE=1 \
CODEX_LINUX_FEATURES=external-app-server-attachment \
make setup-native
```

Do not also enable `shared-app-server-socket`; the two features conflict.

To configure the feature manually instead, copy the example configuration:

```bash
cp linux-features/features.example.json linux-features/features.json
```

Set `linux-features/features.json` to:

```json
{
  "enabled": ["external-app-server-attachment"]
}
```

Build and install a native package on the first install:

```bash
make bootstrap-native
```

If the build dependencies are already installed, use:

```bash
make install-native
```

To use an AppImage instead:

```bash
make build-app
make appimage
./dist/codex-desktop-*.AppImage
```

If you change the feature settings later, rebuild Desktop. Reinstall a native build, or launch the newly built AppImage.

## Attach Desktop

After installing the supported Desktop build, connect it to Codex Session Control:

```bash
codex-session-control setup
```

Setup finds Desktop, makes sure the service is running, and configures the connection. Fully quit and reopen Desktop after setup.

## Specify the Desktop executable manually

Setup normally finds Desktop through the `codex-desktop.desktop` application entry and verifies that the build supports Codex Session Control.

If setup cannot find Desktop automatically, provide the absolute path to its executable:

```bash
codex-session-control setup \
  --desktop-launcher /absolute/path/to/codex-desktop
```

The path must point to the executable itself, not a `.desktop` file. The override changes only how Desktop is located; it does not skip compatibility or safety checks.

## How the connection works

Setup writes a small connection file that tells Desktop which local Unix socket to use. For the default app ID, the file is `${XDG_CONFIG_HOME:-$HOME/.config}/${CODEX_LINUX_APP_ID:-codex-desktop}/app-server-attachment.json`.

The file contains:

```json
{
  "schemaVersion": 1,
  "transport": "unix",
  "socketPath": "/absolute/path/to/app-server.sock"
}
```

Do not edit this file manually. Codex Session Control manages it automatically during `setup`, `enable`, `disable`, and `uninstall`.

Desktop reads the connection file only when it starts. Fully quit and reopen Desktop after `setup`, `enable`, or any connection change.

## Connection behavior

When the connection file is valid, Desktop connects to the existing Codex Session Control service. Desktop does not start, stop, restart, replace, or remove that service. Quitting Desktop closes only its own connection.

Without a connection file, Desktop runs normally without Codex Session Control. If the file is invalid, unsafe, unreadable, or points to an unavailable socket, Desktop refuses the configured connection instead of silently starting a second Codex service.

An attached Desktop task depends on the managed service. A restart-required `update`, or an active `disable` or `uninstall`, refuses before restarting or stopping that service and before removing the connection file when the command is running through the attached task. The refusal does not sign the user out or touch Codex authentication. An independent terminal invocation may still intentionally stop the service and disconnect Desktop.

The supported Desktop build and Codex Session Control must use the same Codex executable, socket, and `CODEX_HOME`.
